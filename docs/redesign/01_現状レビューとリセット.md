## 2. なぜ `digital_v1` は面白くないのか（診断）

依頼にある3つの不満（物語が分かりにくい／遊びが盛り上がらない／UIが文章の選択肢に頼っている）を、コードと文章から具体的に確かめました。

### 2.1 物語が分かりにくい

- **最初の5分で覚えることが多すぎる**。王の要求4つ（三日・銀貨二十枚・騎士は出せぬ・密書）、人物7人（王・大臣・母・リオ・書記官・鳩番・倉番・衛兵・騎士セレン・守将ボルク）、地名（エダ村・ハルデン・北の砦）、日数の計算（会議10日目、糧8日目、徒歩3日、荷車5日、鳩2日、早馬3日）。
- **主人公に「自分の欲しいもの」がない**。主人公は「役目を受けるつもり」で始まり、王と争う動機は「準備が足りない」という実務上の不安だけ。感情を動かす欲求も、恐れも、欠点もありません。
- **相手の本音が「設定の謎解き」になっている**。国庫の逼迫、騎士団との喧嘩、会議の政治、密書の中身。どれも筋は通っていますが、プレイヤーにとっては「調べて当てる事実」でしかなく、王という人物への関心につながっていません。
- **物語の芯が「出発の条件交渉」1回だけ**。転機（最後の鳩）はありますが、主人公が変わる物語にはなっていません。

### 2.2 遊びが盛り上がらない

- **「異を唱える」が実質的にクイズになっている**。`engine.js` の `EVIDENCE` 表は「王の言葉 × 根拠カード → 結果ID」の対応表です。正しいカードを当てれば本音が出て、外れれば我慢が減ります。依頼が避けたいとしている「明らかな正解を順に当てる」構造そのものです。
- **提案が「表計算」になっている**。出発・物資・仲間・報告・密書・荷車の6つの枠に選択肢があり、結果は日数の計算（`reportDay` と `foodDay`）で決まります。人と向き合っているのではなく、条件表を最適化している感覚になります。
- **システムが多い**。我慢、尋ねる、異を唱える（勘／根拠）、言い方、人払い、辞退をちらつかせる、王の一手、転機、6つの条件枠、功績と北の村。1つ1つは妥当でも、合わさると「何をすれば面白いのか」が見えません。
- **相手が1人で、場面が1つ**。読み合いの相手が王だけで、相手を変える、味方につける、対立させる、といった変化がありません。

### 2.3 UIが文章に頼っている

- 選択肢の大半が文になっている。例：「急がれるのは、何か期限があるからでは」「志願騎士セレンの同行を、陛下のお許しで」「紹介状でハルデンの組合から糧を送らせる」。
- 相手の反応は、ほとんどが台詞とログで伝わる。表情、姿勢、場の変化といった視覚的なフィードバックがありません。
- 「手帳」が情報カードの一覧になっていて、読まないと使えません。

### 2.4 根本原因

> **交渉を「正しい情報で正しい条件を選ぶ問題」として作っていた。**

v1 → v2 → digital_v1 と改訂するたびに、仕組みは精密になりました。しかし「相手が人間で、その場で反応してくる」という、交渉ならではの面白さは増えていません。設計書が厳密で長くなっていくこと自体が、この問題の表れです。

## 3. 再利用できるもの・捨てるもの

### 3.1 技術面：再利用を推奨【推奨】

| 資産 | 理由 |
|---|---|
| ロジックと画面の分離（`engine.js` は DOM に依存せず Node でも動く） | 相手の反応を画面なしでテスト・全探索できる。新しいゲームでも同じ構成にする |
| ビルドなしの素の HTML/JS で試作する方針 | Webデモにそのまま使え、検証が速い。ただし本番の技術選定（Steam版）は別に判断する【未決】 |
| `tests/sim.js` の通しテスト、v2 の全探索テストの考え方 | 「支配戦略がないか」「どのルートでも結末に届くか」を機械的に確かめられる |
| 翻訳キー、データ駆動、シード付き乱数の方針（v2 の設計書） | 日英対応の前提を満たす |

コードそのもの（`engine.js` や `ui.js` の中身）は、ルールも画面も新しくなるため流用しません。**構成と考え方だけを引き継ぎます。**

### 3.2 設計上の教訓：引き継ぐ【推奨】

- 情報は「正解の鍵」にしない。1つの事実が1つの正解に直結すると、クイズになる。
- 断られた提案からも何かが分かるようにする（失敗が情報になる）。v2 の良い発想。
- 結末は「勝ち／負け」ではなく、合意の中身で変わる。
- 振り返りで評価語を使わない、唯一の正解として扱わない。
- 紙プロトタイプの「台本にない良い提案こそ知りたい」という姿勢。

### 3.3 捨てる【推奨】

- 物語・舞台・人物（「三日の勅命」、アルダン王など）。ただし企画書の「魔王に向き合う」骨格は、コンセプトA で裏返して使う案があります（`02_物語コンセプト.md`）。
- 「王の言葉 × 根拠カード」の対応表で本音を引き出す仕組み。
- 日数計算で結末が決まる構造。
- 枠ごとに文章の選択肢を並べて提案を組み立てるUI。
- 「手帳（情報カードの一覧）」を読んで使う遊び方。
